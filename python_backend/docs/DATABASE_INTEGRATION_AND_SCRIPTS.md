## 1. Supabase PostgreSQL Integration and Schema

### 1.1 Table Definition: `patients`
The Python backend interacts primarily with the `patients` table in Supabase. The table stores both live patients registered at the kiosk and historical patient records imported from hospital spreadsheets.

| Column Name | PostgreSQL Type | Nullable | Role and Significance |
|---|---|---|---|
| `id` | `uuid` | No (PK) | Unique record primary key (auto-generated by Supabase `uuid_generate_v4()`). |
| `created_at` | `timestamptz` | No | Timestamp of record creation. For live patients, this represents the exact kiosk check-in time (`kiosk_time`). For historical records, set to `reg_start`. Stored in UTC. |
| `patientNum` | `text` | Yes | Patient identifier or queue ticket number (e.g., `"123456"`, `"A-042"`, `"IMP-0001"`). |
| `service` | `text` | Yes | Clinical service category requested by the patient (e.g., `"Consultation"`, `"OPD Screening"`, `"Warfarin"`, `"Benzathine"`, `"ECG"`). |
| `status` | `text` | Yes | Current operational queue status (`"Waiting"`, `"Calling"`, `"In Progress"`, `"Done"`, `"Cancelled"`). Historical rows are set to `"Done"`. |
| `phoneNum` | `text` | Yes | Optional patient contact number for SMS queue notifications. `None` for historical rows. |
| `cubicleNum` | `text` | Yes | Consultation cubicle identifier (e.g., `"R1 C1"`, `"R2 C3"`). Prefix (`'P'` or `'p'`) determines Pediatric vs. Adult clinic classification. |
| `reg_start` | `timestamptz` | Yes | Timestamp when clerical registration / initial triage began. Stored in UTC. |
| `reg_end` | `timestamptz` | Yes | Timestamp when clerical registration / initial triage completed. Stored in UTC. |
| `consult_start` | `timestamptz` | Yes | Timestamp when physician consultation began. Stored in UTC. |
| `consult_end` | `timestamptz` | Yes | Timestamp when physician consultation completed. Stored in UTC. |
| `carryout_start` | `timestamptz` | Yes | Timestamp when carrying out doctor's orders began. Stored in UTC. |
| `carryout_end` | `timestamptz` | Yes | Timestamp when carrying out doctor's orders completed. Stored in UTC. |
| `is_historical` | `boolean` | No (default `false`) | Critical security and filtering flag. Records imported from spreadsheets are flagged `true`. Real-time operational kiosk rows are `false`. |
| `updated_at` | `timestamptz` | Yes | Last modification timestamp. |

### 1.2 Authentication and Key Isolation
- **Principle of Least Privilege:**
  - `SUPABASE_SERVICE_ROLE_KEY`: Used exclusively by internal Python backend operations (`importer.py`, `main.py` commit route) to insert historical records and bypass Row-Level Security (RLS) safely on the server.
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`: Public anonymous key. Allowed for read operations governed by RLS.
  - The service role key is strictly isolated to backend server environments and is never exposed to client-side bundles.

### 1.3 Database Querying Strategies
1. **Full Range Pagination (`fetch_supabase_table`):**
   - Implemented in [main.py:L89-L139](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/main.py#L89-L139).
   - Reuses a persistent `httpx.Client(timeout=30.0)` to eliminate connection handshake overhead.
   - Paginates in chunks of 1000 using HTTP headers `Range: 0-999`, `Range: 1000-1999`, etc.
   - Halts automatically when returning fewer than 1000 rows or upon HTTP 416 (Requested Range Not Satisfiable).
2. **Lightweight Edge Queries (`fetch_supabase_edge`):**
   - Implemented in [main.py:L141-L160](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/main.py#L141-L160).
   - Queries exactly 1 row using `?select=created_at&order=created_at.asc&limit=1` or `created_at.desc`.
   - Used by `/api/available-years` to instantly determine the full historical span without pulling the entire database.

## 2. Standalone Maintenance and Seeding Scripts

### 2.1 Synthetic Patient Generator: `db_seeder.py`
Located at [python_backend/db_seeder.py](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/db_seeder.py).

- **Purpose:** Generates realistic synthetic multi-server queue datasets with realistic stochastic variability for testing, stress-testing, and offline demonstration.
- **Queueing Simulation Details:**
  - **Inter-Arrival Distribution:** Exponential distribution with mean `avg_inter_arrival = 5` minutes (`np.random.exponential(5)`).
  - **Registration Duration:** Exponential distribution with mean `avg_reg_time = 3` minutes.
  - **Daily Volume Variation:** Normal distribution around daily target: `np.random.normal(patients_per_day, scale=8)`.
  - **Operating Shift:** Daily start at 8:00 AM Manila time. Skips Sundays.
  - **Service Routing Probabilities:**
    - Consultation: 45% (`avg_time = 15` min, resource: Doctor)
    - OPD Screening: 10% (`avg_time = 8` min, resource: Triage)
    - OPD Card: 10% (`avg_time = 5` min, resource: Admin)
    - Warfarin: 10% (`avg_time = 10` min, resource: Nurse)
    - Benzathine: 8% (`avg_time = 12` min, resource: Nurse)
    - ECG: 7% (`avg_time = 20` min, resource: Technician)
    - Refill Prescription: 5% (`avg_time = 5` min, resource: Admin)
    - OPD Reschedule: 5% (`avg_time = 5` min, resource: Admin)
  - **Routing Logic:** Only `Consultation` and `OPD Screening` pass through the Registration stage (`reg_start`, `reg_end`). Other specialized services go directly to their respective service stations (`reg_start = None`, `reg_end = None`).
  - **Output File:** Writes to [python_backend/simulated_patients.csv](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/simulated_patients.csv).

### 2.2 Seed Importer: `import_seeder_to_supabase.py`
Located at [python_backend/import_seeder_to_supabase.py](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/import_seeder_to_supabase.py).

- **Purpose:** Reads `simulated_patients.csv` and uploads records to Supabase `patients` table via REST API.
- **Batch Size:** Hardcoded batch size of `1000` records per HTTP POST.
- **Headers:** `Prefer: return=minimal` to conserve network bandwidth and database memory.
- **Prefix:** Prefixes patient ticket numbers with `seed-` (e.g., `seed-CON-001`) to allow easy isolation from authentic hospital records.

### 2.3 Automated Seeding Shell Script: `auto_seed.sh`
Located at [python_backend/auto_seed.sh](file:///home/jensen/Github-Repositories/Heart_Check_PHC/python_backend/auto_seed.sh).
