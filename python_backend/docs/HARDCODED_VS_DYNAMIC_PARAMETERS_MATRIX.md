# Hardcoded vs. Dynamic Parameters Matrix

This document provides a comprehensive, exhaustive audit and lookup matrix of every configuration variable, operational threshold, query parameter, model hyperparameter, timeout, and constant across the entire Heart Check PHC Python backend.

---

## 1. Classification Categories

Every parameter in this system belongs to one of the following categories:
- **Hardcoded Constant:** Fixed value defined in source code; changing requires editing the Python file and reloading the server.
- **Environment Variable:** Configured outside code in `.env.local` or OS environment variables; loaded at startup.
- **Query Parameter:** Dynamically supplied by the frontend or client via HTTP GET/POST URL parameters.
- **Path Parameter:** Dynamically supplied as part of the URL route path.
- **Request Body:** Transmitted in HTTP payload bytes or JSON bodies.
- **Database Attribute:** Dynamically fetched from Supabase PostgreSQL tables.
- **Algorithmic Calculation:** Computed dynamically at runtime from patient data.

## 3. Analysis: What is Hardcoded vs. What Can Be Made Dynamic

### 3.1 Hardcoded Values That Are Clinically Fixed
These parameters represent immutable physical infrastructure or official clinical documentation standards:
1. `MAX_ADULT_CUBICLES = 5` and `MAX_PEDIA_CUBICLES = 5`: Philippine Heart Center's physical building layout comprises 1 Adult Consultation room (5 physical cubicles) and 1 Pediatric Consultation room (5 physical cubicles). Making these dynamic would require physical clinic remodeling.
2. `OPD_TARGET_MINUTES = 150`: The official thesis scope and hospital time-and-motion benchmark established by hospital administration.
3. `EXAMINE_TREAT_TARGET_MINUTES = 105`, `EVALUATE_TARGET_MINUTES = 30`, `CARRYOUT_TARGET_MINUTES = 15`: Exact printed categories on the physical PHC Out-Patient Division time and motion tally sheet.
4. `PHC_CONSULTATION_SHIFT_HOURS = 7`: Established outpatient clinic operating shift length used in hospital formulas.

### 3.2 Hardcoded Values That Could Be Dynamic / Configurable
These parameters represent operational assumptions that could be exposed as administrative settings:
1. **Target Utilization Cap (`target_utilization = 0.80`):** Currently defaults to 80% in `staffing.py`. Could be exposed as an administrative workstation slider allowing hospital managers to model 75% or 85% staffing scenarios.
2. **Consultation Routing Proportion (`p_consultation = 0.65`):** Currently defaults to 65% in `report.py`. In live operation, this could be derived dynamically from the empirical service distribution:
   $$\hat{p}_{\text{consultation}} = \frac{\text{Count}(\text{purpose} = \text{'consultation'})}{\text{Count}(\text{all patients})}$$
3. **Clinic Allocation Proportions (`p_adult = 0.50`, `p_pedia = 0.50`):** Currently defaults to a 50/50 split in `report.py`. Could be computed dynamically from the ratio of Adult vs. Pediatric patient registrations.
4. **Cache TTL (`CACHE_TTL_SECONDS = 300`):** Currently 5 minutes in `main.py`. Could be driven by an environment variable `CACHE_TTL_SECONDS` to allow tuning for high-traffic environments or faster test cycles.
5. **ARIMA Order (`ARIMA_ORDER = (1, 1, 1)`):** Currently fixed. Could incorporate automated hyperparameter grid searches (`auto_arima` or AIC grid evaluation over $(p, d, q) \in [0, 2]$) when analyzing long multi-year series.
